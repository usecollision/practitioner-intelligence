## Beliefs
- Vanity metrics put optics before rigor; most come from inexperience with data storytelling (OPINION, T1).
- A metric can be meaningful but not actionable; over-applying "actionability" produces safe, useless metrics (T1).
## Frameworks
- Vanity Metric Test (FRAMEWORK, T1): a metric is vanity if it (1) lacks context, (2) has unclear intent, (3) doesn't guide action/learning.
- North Star Inputs: NSM is a lagging multi-year output; teams need input metrics as bridge (FRAMEWORK, T1).
## Principles
- Metric intent must be explicit: define the measure, what it proxies, why it matters (T1).
- NSM should be "a bit out of reach"; teams shouldn't wake up trying to move it directly (T1).
- Threshold metrics beat averages: "% of users who performed high-value action" (T1).
- Once a metric becomes a target it risks being gamed — Goodhart in practice (T1).
## Decision rules
- IF a metric lacks "compared to / as input into / balanced by" THEN it's vanity (T1).
- IF a metric rises but no tactic changes THEN drop it (T1).
- IF teams stress about controlling the NSM THEN add input metrics (T1).
- IF a "magic metric" search runs >months THEN stop; pick proxy + iterate (T1).
- IF uncertainty reduced slightly THEN act; don't wait for 100% certainty (T1).
## Failure modes
- Celebrating numbers that don't change strategy when they drop (T1).
- NSM paralysis: team disengages from metric it can't influence (T1).
- Remnant-era engagement metrics (page views, time on page) as proxies (T1).
## Conditions
- Product teams with instrumentation; pre- and post-PMF (T1).
