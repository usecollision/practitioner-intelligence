## Landing page copy
- **Consensus**: page copy is funnel step, not an island (Price T2; Wiebe T1); message-match beats polish (Aagaard: Saxo +99.4%, Bettingexpert +31.5% — EMPIRICAL); hero must pass the 5-second clarity test (Wiebe); every claim needs proof (Ogilvy, Wiebe); LIFT factors (value, relevance, clarity, urgency, distraction reduction, anxiety reduction) are the diagnosis lens (Widener, FRAMEWORK — organizing device, no comparative win-rate evidence).
- **Disagreement**: long vs short pages (decision-stage buyers want length, awareness wants brevity — resolved by Price's funnel-stage mapping); emotional vs data-driven headline choice (Wolf vs Laja — condition: emotional when analytics shows a leak but not why).
- **Failure**: hero describing the product instead of the outcome; optimizing the page when the funnel step or offer is the bottleneck (Price); proof mismatched to ICP; wall-of-text (scanner test fails).
- **Collision Method**: baseline analytics first (Price) → funnel position determines structure/length → message-match audit (Aagaard/Wolf: is value prop clear in the first 5 seconds?) → LIFT diagnosis for leaks (value/relevance/clarity/urgency/distraction/anxiety) → write 5+ headline variants incl. verbatim customer language (Wiebe) → five-second test before A/B.
- **Decision rules**:
  1. IF no baseline conversion data for the step THEN fix measurement before rewriting (Price — FRAMEWORK, T2).
  2. IF the value prop isn't clear in 5 seconds THEN fix message-match before layout/tests (Aagaard — EMPIRICAL, T1).
  3. IF drop-off is below the fold THEN check anxiety/distraction factors (LIFT) before rewriting copy (Widener — HEURISTIC).
  4. IF traffic can't support conclusive tests THEN use five-second tests + funnel observation, not A/B (Wiebe — FRAMEWORK, T1).
  5. IF the offer is comparable-away THEN stack the offer before more copy (Hormozi — HEURISTIC, T3).

## Email copy
- **Consensus**: subject+preview are one two-line ad (Schwedelson); stage-appropriate copy over promo-everything (White lifecycle; Geisler behavior-branching); human voice wins (Belgray; Geisler founder welcome email); one CTA per email (Chaperon); value-first CTA labels; honest subject (deliverability is reputation, Atkins).
- **Disagreement**: frequency (Geisler "more often than you think" vs Atkins "more isn't always better" — condition: high-engagement lists vs reputation risk at scale); opens vs clicks post-MPP (Schwedelson optimizes opens +15-28% lifts vs White clicks — condition: B2B/Gmail mixes retain open signal, Apple-heavy consumer lists don't).
- **Failure**: subject/preview written in isolation; every email a sales email; clickbait subjects (spam complaints); time-based-only sequences (Geisler); optimizing email while landing page kills conversion (Pay).
- **Decision rules**:
  1. IF subject and preview don't read as one continuous hook THEN rewrite the pair (Schwedelson — EMPIRICAL, T2).
  2. IF sending to a stale segment THEN winback/re-permission/prune before more sends (White — FRAMEWORK, T1).
  3. IF engagement is high and list permissioned THEN frequency can rise; IF complaints/spam rise THEN cut frequency (Geisler vs Atkins — DISAGREEMENT, conditional).
  4. IF Apple-Mail mix dominates THEN trust clicks, not opens (White — FRAMEWORK, T1).
  5. IF the email's CTA lands on a broken/unclear page THEN fix the page first (Pay — FRAMEWORK, T2).

## Ad copy
- **Consensus**: sophistication and awareness determine claim type and entry point (Schwartz — T1-canonical); platform constraints are design inputs, not afterthoughts; test creatives, not audiences (Dara Denney — EMPIRICAL, T2); one variable per variant; first line of primary text is the hook (Meta truncation ~125 chars).
- **Disagreement**: copy-led vs creative-led (Schwartz copy claims vs Denney creative testing — resolution: copy carries the claim, creative carries the hook; both tested together as the creative unit); long-form vs short-form copy (platform decides, not preference).
- **Failure**: one universal ad resized across platforms; hook buried after pleasantries; RSA sets repeating one idea; CTA mismatch with funnel stage; multiple variables changed per variant (nothing learnable).
- **Collision Method**: awareness level per placement (cold = problem-aware entry; warm = offer entry) → sophistication stage picks claim type → write 10-15 headlines per angle → primary text hook in line 1 → CTA matched to stage → variant matrix isolating one variable → let volume accrue before judging.
- **Decision rules**:
  1. IF market is sophistication stage 3+ THEN lead with mechanism/proof, not outcome claims (Schwartz — FRAMEWORK, T1).
  2. IF audience is cold THEN low-friction CTA and problem-entry; IF warm THEN direct ask (Schwartz — FRAMEWORK, T1).
  3. IF budget is $5k-30k/mo THEN test 1-3 new creatives/week in one ASC campaign, cap ~10 creatives (Denney — EMPIRICAL, T2).
  4. IF a creative wins THEN iterate the winner 10 ways before testing brand-new concepts (Denney — HEURISTIC, T2).
  5. IF truncation cuts the message THEN the hook window was wasted — rewrite line 1 (platform spec + Denney — HEURISTIC).

## Video scripts
- **Consensus**: stay-or-scroll decision happens in 0.3-0.8s; 50-70% of leavers exit in the first 1-2 seconds; hook window 1.5-3s; layered hooks (visual+audio+text) beat single-element ~3x; sound-off viewing dominates (60%+) so text must carry the story; core message inside first 3s ≈ +60% total retention (Billo analysis — EMPIRICAL, T2); retention beats every 2-4s (Opus data).
- **Disagreement**: entertainment vs promise hooks by niche (educational favors direct promise; entertainment favors interrupts — condition: content type decides); TikTok (0.8-1s window) vs Shorts (1.5-2s) vs Reels (visual-first) — platform decides hook layer priority.
- **Failure**: intro wasted ("Hi, I'm..."); hook without payoff; no pattern breaks (static talking head); one script stretched across platforms; CTA mismatched to goal; fabricated stats (Denney compliance + legal).
- **Decision rules**:
  1. IF the first frame has setup/logo/dead air THEN cut it — that's where 50-70% of loss happens (retention data — EMPIRICAL, T2).
  2. IF sound-off viewers dominate THEN the story must survive mute-only (on-screen text carries claims) (platform data — EMPIRICAL, T2).
  3. IF any 5-second stretch has no pattern break THEN rewrite (Opus retention data — EMPIRICAL, T2).
  4. IF testing paid video THEN produce 2-3 hook variants of one body; test hooks before rewriting bodies (Denney — HEURISTIC, T2).
  5. IF the payoff doesn't resolve the hook's promise THEN cut the curiosity — algorithms and viewers both penalize mismatches (Billo/postigniter — EMPIRICAL, T2).

## Brand voice
- **Consensus**: voice is HOW, message is WHAT — different layers (Belgray vs Wiebe disagreement resolved as layers); voice comes from customer language + founder voice, not competitor cloning (Handley, Belgray); traits must be concrete (plainspoken > authentic); tone shifts with situation while voice stays constant (Handley).
- **Disagreement**: personality-led conversion (Belgray: people want relatable) vs research-led (Wiebe) — condition: commoditized inboxes/social favor voice; unfamiliar categories favor message-match.
- **Failure**: abstract traits nobody can act on; voice cloned from competitors; customer phrases pasted unadapted; one tone for all situations (cheerful during outage); guides too long to be adopted.
- **Decision rules**:
  1. IF copy reads like every competitor THEN rebuild voice from customer language + founder samples, not category norms (Belgray/Handley — FRAMEWORK, T2).
  2. IF a trait can't be turned into 3 writing behaviors THEN rename it until it can (Handley — HEURISTIC, T1).
  3. IF the situation is an apology/outage THEN drop playfulness, raise directness (Handley tone ranges — HEURISTIC, T1).
  4. IF a rewrite doesn't sound like the founder talking to a friend THEN revise (Belgray — HEURISTIC, T2).
  5. IF the guide exceeds ~3 pages THEN cut — length kills adoption (Handley — HEURISTIC, T1).

## Messaging hierarchy
- **Consensus**: hierarchy derives from positioning (Dunford — T1); 3-5 outcome pillars, not feature lists; each pillar maps to proof and an objection; taglines come from Pillar 1, not a thesaurus; consistency test: any asset claim must trace to a pillar (Dunford, Pierri).
- **Disagreement**: message map (many boxes) vs narrative (Raskin story) — condition: stable markets favor the hierarchy artifact; shifting markets need the story; both require evidence-first (Dunford/Raskin convergence on evidence).
- **Failure**: pillars that are features; >5 pillars (collapses into feature list); proof mapped to wrong pillar; hierarchy written but never cascaded; copywriters kept out (adoption fails).
- **Decision rules**:
  1. IF positioning doesn't exist THEN do the positioning work first — hierarchy inherits it (Dunford — FRAMEWORK, T1).
  2. IF a pillar has no proof THEN flag it as an assertion with an owner, never ship it as fact (Dunford evidence-first — FRAMEWORK, T1).
  3. IF more than 5 pillars emerge THEN merge — hierarchy collapses into a feature list beyond 5 (Dunford/Pierri — HEURISTIC).
  4. IF a tagline says nothing a competitor wouldn't say THEN reject it (positioning synthesis — FRAMEWORK, T1).
  5. IF an existing asset contains a claim that traces to no pillar THEN delete it or re-research it (consistency test — FRAMEWORK, T1).

## Value proposition
- **Consensus**: value = delta between before/after, quantified where possible (Wiebe, Dunford); JTBD framing: job/pains/gains/success criteria in customer words (Moesta/Ulwick — T1); uniqueness via "only" test (Neumeier, Dunford); value prop written 80% in customer vocabulary (Shah, Wiebe).
- **Disagreement**: story-first JTBD (Moesta: reconstruct timeline) vs outcome-first (Ulwick: strict outcome syntax, customers can't articulate needs) — condition: emotional/rare purchases → story; operational/measurable jobs → outcome statements.
- **Failure**: feature lists disguised as value props; unlabeled estimates presented as measured; claims any competitor can make; marketing-speak disconnected from the language bank; claiming the category instead of the delta.
- **Decision rules**:
  1. IF no customer language exists THEN research before writing the value prop (Wiebe/Shah — FRAMEWORK, T1).
  2. IF a competitor could paste their name into the claim THEN it's table stakes, not differentiation (Neumeier "only" test — FRAMEWORK, T1).
  3. IF a quantified claim is estimated THEN label it estimated or drop it (skill standard + research synthesis — HEURISTIC).
  4. IF the job is emotional/rare THEN reconstruct the switch story; IF operational THEN use outcome statements (Moesta vs Ulwick — DISAGREEMENT, conditional).
  5. IF the value prop can't pass "would the customer say this?" THEN rewrite in customer words (Shah — FRAMEWORK, T1).

## Customer language bank
- **Consensus**: verbatim capture is non-negotiable — quirks are the signal (Wiebe "slightly revise", Shah, Moesta); record and transcribe, don't paraphrase (Clozd); organize by stage → category (writing index) and pain → theme (research index); recruit the full spectrum (winners AND losers) for research feeding the bank (Revella, Moesta).
- **Disagreement**: how many interviews before the bank is usable (JTBD school 5-8 per job vs saturation review 9-17 vs win/loss 20+/segment — condition: narrower job = fewer; prioritizing/sizing = more or quant).
- **Failure**: sanitizing phrases into marketing speak; keeping vague phrases ("great product"); bank built and never used; no source/stage tags; one-time artifact instead of living document; AI personas trained on generic internet instead of own transcripts (ziellab).
- **Decision rules**:
  1. IF a phrase doesn't name a concrete pain/outcome/comparison/trigger THEN don't bank it (skill standard + Wiebe — HEURISTIC).
  2. IF a phrase is high-emotion AND self-contained THEN tag it as a headline candidate (Wiebe — HEURISTIC).
  3. IF the bank lacks a consumer of the phrases (an asset to write) THEN the extraction is premature (Wiebe: research feeds writing — FRAMEWORK, T1).
  4. IF mining win/loss THEN ≥20 interviews per segment before trusting themes (Clozd — EMPIRICAL, T1).
  5. IF using AI to build personas THEN train it on your transcripts, never on general internet content (ziellab — HEURISTIC, T2).

## Objection handling
- **Consensus**: objections are mined from research (reviews 2-4 star, sales call notes, churn interviews) not invented; rank by frequency × severity, handle top 5; formula: acknowledge → reframe → proof → pivot; pre-emptive copy beats reactive FAQ (Wiebe, Ogilvy); strongest objection-killer goes nearest the CTA; price objections usually mean value clarity, not price (offer-design synthesis — FRAMEWORK, T1).
- **Disagreement**: how much objection content belongs on the page (FAQ-at-bottom school vs pre-emptive-in-prose school — condition: pre-emptive for top 2-3 objections, FAQ for the long tail).
- **Failure**: rebuttals that argue ("Actually..."); generic proof; handling every objection equally; objection copy buried in unscrolled FAQ; invented statistics.
- **Decision rules**:
  1. IF sales hears the same objection on every call THEN treat it as a messaging gap, not a sales problem (research synthesis — FRAMEWORK, T1).
  2. IF the objection is price THEN check value clarity first — price objections usually mean the value is unclear (offer-design rule — FRAMEWORK, T1).
  3. IF the objection is partly true THEN admit the part that's true (honesty raises credibility) (skill standard — HEURISTIC).
  4. IF placing objection-killers THEN put the strongest (guarantee, case study) adjacent to the CTA (conversion synthesis — HEURISTIC).
  5. IF a rebuttal starts by dismissing the concern THEN rewrite to acknowledge first (skill standard — HEURISTIC).

## Case study builder
- **Consensus**: metrics-first headline (outcome + delta + timeframe); challenge/solution/results with proof placed at the moment of doubt, not stacked at the end; customer's words verbatim; written sign-off on every number and quote; story selection requires measurable outcome + ICP representativeness + permission (Wiebe, Ogilvy, Clozd).
- **Disagreement**: how much process detail (implementation narrative fans vs metrics-table-first readers — condition: technical buyers want implementation; exec buyers want the table).
- **Failure**: story led by logo instead of outcome; thin challenge section; unverified numbers; one PDF for every channel; solution written as feature tour; "great relationship" story shipped as a case study (that's a testimonial).
- **Decision rules**:
  1. IF no verifiable numbers AND no written permission THEN don't build the case study — it's a testimonial at best (skill standard — HEURISTIC).
  2. IF the headline doesn't lead with an outcome metric THEN rewrite (metrics-first rule — HEURISTIC).
  3. IF a number can't be verified from system data THEN label it an estimate or drop it (proof discipline — HEURISTIC).
  4. IF repurposing THEN every variant keeps the same verified numbers and metrics-first logic (skill standard — HEURISTIC).
  5. IF the target reader is executive THEN lead the results with the metrics table; IF technical THEN include implementation detail (conditional — HEURISTIC).

## Sales deck
- **Consensus**: Raskin's 5 elements — big change in the world, land on the positive side (Promised Land), the journey (why now), the as/if (proof of the change), the new narrative (everyone tells the story) (Raskin — T1); headline = full-sentence claim (deck readable by headlines alone); ≤8 slides to product (Raskin heuristic); proof lands where the biggest doubt sits; ask appears once at the end.
- **Disagreement**: Raskin narrative-first vs Dunford evidence-first (condition: shifting market + credible big change → Raskin; stable market → evidence/market-frame); investor vs sales deck structure (different audiences, different arcs).
- **Failure**: feature tour instead of narrative; headlines that are labels; proof dumped on one slide; ask buried mid-deck; two decks fighting in one file; bullet walls.
- **Decision rules**:
  1. IF no credible big change exists THEN don't force the Raskin narrative — use evidence-first (Raskin vs Dunford — DISAGREEMENT, conditional).
  2. IF a headline is a label ("Our Solution") THEN rewrite as a claim (Raskin — FRAMEWORK, T1).
  3. IF the product appears before slide 4-5 in a sales deck THEN the problem hasn't been felt yet (Raskin — HEURISTIC).
  4. IF the ask is missing or appears twice THEN fix — once, at the end, as the logical conclusion (Raskin — HEURISTIC).
  5. IF headline-only read doesn't tell the full story THEN restructure (Raskin — FRAMEWORK, T1).

## Thought leadership
- **Consensus**: earned insight is the raw material — content anyone could write from public sources is not thought leadership (Perell: surprise/experience; Cole: frameworks from lived practice); one idea per essay; specifics over sweep; the reframe must be quotable and falsifiable; POV structure: default belief → why it breaks → evidence/scar tissue → reframe → implication → open loop (Perell/Cole convergence).
- **Disagreement**: essay length (Perell: 100+ hour essays, meander toward surprise vs Cole: 300-word atomic essays, volume + frameworks — condition: flagship essays vs daily practice; both agree one idea per piece and surprise/insight over polish).
- **Failure**: summarizing the industry; contrarian for its own sake; unearned opinions without data/story; corporate voice scrubbing the personality; topics chosen for traffic instead of earned insight; no distribution plan (Simmonds: work starts after publish).
- **Decision rules**:
  1. IF a competent stranger could write it from public sources THEN it's content, not thought leadership (Perell/Cole — FRAMEWORK, T2).
  2. IF the idea can't be framed as a belief shift THEN find the shift or drop the topic (skill standard + Perell — HEURISTIC).
  3. IF the claim isn't falsifiable THEN it's an opinion, not a POV (skill standard — HEURISTIC).
  4. IF the author wouldn't defend it in a room with the people disagreed with THEN rework (room test — HEURISTIC).
  5. IF the essay lacks the author's specific numbers/stories/mistakes THEN add scar tissue (Perell surprise principle — HEURISTIC, T2).

## Content repurposing
- **Consensus**: repurpose/remix/reshare (Simmonds — T1); create once, distribute forever (Simmonds book); only ~20% of an audience sees any single post — resharing serves the 80% who missed it (Simmonds — EMPIRICAL/T2); reformat, never repost (Cole: republish with platform-native adaptation); track variants back to the source atom (Simmonds: work after publish); Four E's — educate, engage, entertain, empower (Simmonds).
- **Disagreement**: republish-everywhere-as-is (Cole) vs channel-native rewriting (Simmonds) — resolution: Cole's republishing works for personal essays on text platforms; Simmonds' channel-specific remixing for branded content; both agree the voice stays constant.
- **Failure**: copy-paste reposts; extracting quotes instead of ideas; flooding all platforms in 24h; repurposing everything indiscriminately; no tracking from variant to source (nothing learnable); forcing every unit into every format.
- **Decision rules**:
  1. IF an asset didn't perform AND isn't evergreen THEN don't repurpose it (Simmonds — HEURISTIC, T2).
  2. IF the audience only saw ~20% of the first post THEN reshare is serving, not spamming — space same-topic variants 48-72h (Simmonds — EMPIRICAL/T2).
  3. IF a unit can't stand alone without the source's context THEN it's not extractable (skill standard — HEURISTIC).
  4. IF a unit wins in one format THEN remake it in the others (Simmonds/Cole — HEURISTIC).
  5. IF repurposing a video THEN treat clip selection as the hook problem — start at the most dramatic moment (Opus/Denney — HEURISTIC, T2).

## Content strategy
- **Consensus**: audience-first, not keyword-volume-first (Law — T1); traffic potential over volume (Soulo — EMPIRICAL, T1); intent decides format and depth (Dean/SERP — FRAMEWORK); distribution is half the job (Simmonds); quality floor over mass production (2024-26 scaled-content enforcement — EMPIRICAL, T1); content must convert through the funnel, not just rank (Dunning bottom-funnel).
- **Disagreement**: topical authority depth (Gubur) vs audience-first brevity (Law) — condition: competitive informational niches favor exhaustive coverage; B2B/SaaS favor opinionated, audience-problem content; content-type mix (60/20/10/10 is a heuristic, not a law).
- **Failure**: writing what the company finds interesting instead of what ICP needs; no distribution plan ("build it and they will NOT come" — Simmonds); publish-and-forget (decay treadmill — Indig); mass templated pages without differentiation (Google enforcement); high-volume keywords that convert no one (Soulo/Dunning).
- **Decision rules**:
  1. IF a keyword has volume but no buyer intent THEN skip it (Soulo/Dunning — EMPIRICAL, T1).
  2. IF the topic doesn't map to a defined buyer's problem THEN don't publish it (Law — FRAMEWORK, T1).
  3. IF content is published without a distribution checklist THEN the plan is incomplete (Simmonds — FRAMEWORK, T1).
  4. IF a page underperforms for 3-6 months THEN update/merge/kill — don't publish alongside it (Indig decay — EMPIRICAL, T1).
  5. IF planning programmatic/templated content THEN require a per-template quality floor (Indig/Google enforcement — EMPIRICAL, T1).

## Localization
- **Consensus**: depth ladder translation → localization → transcreation (Lokalise — FRAMEWORK); transcreation = same feeling and action in the new culture (Lokalise; PoliLingua); lock the narrative frame, let each market rewrite the punch line (Mastercard transcreation — EMPIRICAL, T2); same insight, local words/casting (Snickers +15.9% global sales — EMPIRICAL, T2); native review + in-market SME + back-translation for high-risk claims; glossary + translation memory enforce consistency (all three vendors converge); platform automation should follow a designed process, not wrap a broken one (Phrase implementation guidance — HEURISTIC).
- **Disagreement**: AI/MT-first vs human-first (Transifex TQI auto-approve 62% strings straight to production vs traditional human review — condition: volume/product UI strings favor AI+thresholds; brand/marketing copy favors human transcreation); waterfall vs continuous localization (condition: product release cadence decides).
- **Failure** (documented): literal slogan translation that inverts meaning (Pepsi China "ancestors back from the grave"; HSBC "Assume nothing"→"Do nothing" $10M rebrand; Schweppes "Tonic Water"→"Toilet Water"; American Airlines "Fly in Leather"→"fly naked"); culture-specific symbols (Pampers stork in Japan); untested names (Coca-Cola "wax toad", GM Nova); no native review (register errors); 29% of marketers admit a translation/cultural blunder damaged brand reputation (Lokalise 2026 survey — EMPIRICAL, T2).
- **Collision Method**: per-market depth decision (translation/localization/transcreation) → market value-driver research (local reviews, forums, competitor messaging) → adapt message, not just words (keep promise/voice; swap examples, idioms, humor) → localize proof and numbers (local customers, units, benchmarks) → two-reviewer loop (native copywriter + in-market SME; back-translation for high-risk) → glossary + TM + decisions log → track per-market performance against home baseline.
- **Decision rules**:
  1. IF a joke needs a footnote to make sense THEN cut it — humor transfers poorly (Lokalise — HEURISTIC).
  2. IF the claim itself doesn't survive the market THEN the problem is the value prop, not the copy (skill standard — HEURISTIC).
  3. IF the content is legal/medical/financial/safety THEN back-translation review is mandatory (Lokalise — HEURISTIC).
  4. IF scaling to many locales with continuous releases THEN use TMS with TM+glossary and conditional routing (MT below threshold, human above) (Phrase/Transifex — FRAMEWORK, T2).
  5. IF adopting a localization platform THEN pilot one content type + 2-3 language pairs before full rollout (Phrase — HEURISTIC, T2).
  6. IF a market's buying criteria differ materially THEN re-run value-prop prioritization per market, don't translate the home hierarchy (skill standard + transcreation cases — FRAMEWORK, T2).

## Cross-discipline failure knowledge (new, 2026-08-15)
- Publishing as the finish line: "the work happens after you press publish" (Simmonds) — the single most repeated failure across content skills.
- Testing audiences instead of creatives (Denney) — creative is the highest-leverage paid variable.
- Wasting the first 1-2 seconds of video (retention data) — 50-70% of loss is front-loaded.
- Translating instead of transcreating for emotional/brand content (Lokalise transcreation cases).
- Generic AI content without voice or earned insight (Cole/Perell/Simmonds convergence: AI as consultant, not author).

## Evidence evaluation
- **EMPIRICAL (large-N/platform data)**: Billo 3-second retention (+60%); 50-70% first-2-second loss; layered hooks 3x; Snickers +15.9% sales; Mastercard 53 languages/80% awareness; HSBC $10M rebrand; Lokalise 29% blunder survey; Schwedelson +15-28% subject/time lifts; Aagaard +99.4%/+31.5% message-match.
- **FRAMEWORK (high convergence)**: Schwartz sophistication; Dunford hierarchy; Raskin 5 elements; Simmonds Three Rs/Four Es; LIFT (weakly validated); JTBD (Moesta/Ulwick).
- **HEURISTIC**: hook length 1.5-3s; 2-4s cut cadence; ~20% audience reach per post; 3-page voice guide cap; ≤8 slides to product; 5-8 vs 9-17 vs 20+ interview counts.
- **OPINION/self-reported (T3)**: Denney's $100M spend credentials (T2 via industry reputation); Transifex 62% auto-approve (vendor data); Perell's 100-hour essays (self-reported).

## Outliers worth investigating
- **Transifex TQI auto-approval** (MQM-based scoring, 62% strings ship with minimal edits) — if vendor data holds, it's the first scalable quality gate for AI translation.
- **Perell's CRIBS method** (confusing/repeated/interesting/boring/surprising) — a formal listener-response filter for testing ideas before writing; directly applicable to hook and topic selection.
- **Simmonds' "reshare serves the 80%"** — reframes reposting from spam to service; testable frequency rule.
- **Denney's "ugly ads"** — problem-agitating lo-fi creative outperforms polished creative for new audiences; anti-precision signal.
- **Phrase's implementation warning** ("configuring a platform around a broken process") — a generalizable adoption rule for any marketing tooling.
